## How to call a team

Paste this at the top of the chat (Grok ALA, Cursor, or Slack):

```text
CALL: <DEPARTMENT>
Symptom: <what is broken or what to add>
Fan surface: <tab or route>
Admin desk: <Expo /admin/... or Next /...>
Do not: <other departments>
Read first: docs/agents/TEAMS.md#<anchor>
Gate: pnpm typecheck && pnpm docs:check
```

Say the department in plain words. These calls map to available specialist instruction definitions:

`CALL: DESIGN` · `CALL: ENGINEERING` · `CALL: FULLSTACK` · `CALL: BACKEND` · `CALL: LEGAL` · `CALL: COMPLIANCE` · `CALL: VOICE` · `CALL: QA`

13. **Redundancy and exit plan stays current (2026-10-19, owner).** Any app change keeps the move-off-Supabase plan and backup version current automatically: `scripts/exit-map.mjs` regenerates `docs/engineering/exit/EXIT_INFRASTRUCTURE_MAP.md` (plan version = what the app uses on Supabase), the project Stop hook runs it at the end of every Claude session, and `pnpm exit:map:check` (in `pnpm check` and CI) fails on a stale map, a coverage gap (Edge Function outside the self-host allowlist, unmapped Auth method) or an unannounced change. The session that made the change announces it with `pnpm exit:map --acknowledge --by "<session>"`; `EXIT_SYNC` owns that notice in `docs/agents/EXIT_CHANGE_LOG.md`, routed to `EXIT_DATABASE` / `EXIT_SERVICES` / `EXIT_CLOUD` and the partner roles, who record their review. `REDUNDANCY_LEAD` closes notices. **Reading home:** [docs/engineering/exit/](../engineering/exit/README.md) (charter, map, security report, runbooks, plans). Charter: [REDUNDANCY_TEAM](../engineering/exit/REDUNDANCY_TEAM.md).
10. **Concurrent sessions (2026-10-12).** Another tool's session (Codex, Cursor, a person) may edit the same tree while an agent works. Codex and people are not registry agents, and their edits do not change who owns a file.
    - **Claim.** Before editing a shared file, claim it in the task tracker's Status table (for example the Status table in `docs/agents/ADM-01.md`): name the session, the files, and the time. Release the claim in the same table when done.
    - **Check times.** Check the file's modified time (`stat` or `ls -l`) before each edit. If it changed since you read it, read it again before you write.
    - **Never revert.** Do not revert or overwrite another session's work without the owner. If two edits conflict, stop and report both.
    - **Conflicting instructions.** When the owner has given two sessions conflicting instructions, ask the owner. Do not pick one yourself.
    - **Owner review still applies.** An outside session's edit to a specialist-owned file still needs that owner's review. For example, a chart-kit prop change needs `DESIGN` + `ACCESSIBILITY`, and a `globals.css` change needs `ADMIN`'s approval.
