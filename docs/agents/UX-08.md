# UX-08 — sport field lines and scoreboard digits

**Owner request (2026-10-21):** "add a touch of enhancement on UI/UX … fun, sporty where necessary … dynamic
enough for any user." Owner chose **both, lightly** (sport field lines + scoreboard digits) on the athlete
profile, the QR donate page, Spotlight and Local game cards.
**Direction:** inside the owner-selected Calm Island palette (one jade brand colour, gold only for awards,
ember only for live). No new colours, fonts or motion.
**Executor:** Claude Code (Opus 5.5) root session, with an independent read-only review subagent.

## What changed

| Piece | Source | Notes |
| --- | --- | --- |
| Sport → surface | `data/sportField.ts` | Keyword match so admin-added sports still get a surface; unknown or missing → generic field (outline, halfway line, centre circle). 11 kinds. |

`hooks/useViewerSport` picks the sport: the signed-in athlete's `athlete_sport`, otherwise the generic field
(fans, parents, boosters, guests). It reads the existing profile only and never throws outside AuthProvider
(`useOptionalAuth`). The generic field now uses corner arcs instead of a full outline so it never reads as a
second card border. Home's video feed stays clean (no lines over video). Admin desks keep the report format.

## Fixed after the rollout request

- **Athlete profiles on development:** root cause was in source, not drift. Tag approval made `reels_feed.player_id`
  a CASE expression, so PostgREST cannot follow it to `players`; the `players(...)` embed fell back to the
  `reel_tag_rejections` junction (locked) → 42501 for everyone. `lib/reels.ts` now selects clips without the embed
  and attaches athletes from one `players` read by the view's (privacy-blanked) `player_id`; the duplicate
  embed/no-embed tiers collapse into one list. Regression: `lib/__tests__/reelsPlayers.test.ts`. Verified on the
  development project: Marcus Vance's profile loads with Highlights.
- **Fresh web loads landing on Home:** not reproducible with the tab visible (10 fresh loads across 5 routes stayed
  put, with a temporary navigation logger, removed). Earlier bounces all happened in a hidden background tab, where
  Chrome pauses frame callbacks. No routing code changed.
